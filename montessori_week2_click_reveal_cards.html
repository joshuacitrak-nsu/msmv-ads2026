Presenting: Click a face-down card to reveal that card, or click Reveal next to unfold each program in order. Use Reset for a fresh run. Answers are hidden separately, so you can let students reason first. The entire lesson scrolls down one page.
0–12 minutes · Part 1

Variable review + complexity

Revisit assignment and reassignment, then add arithmetic and string manipulation.

Talk track“Last week, we learned that a variable is a name for a stored value. Today our challenge is to follow what happens to that value, one instruction at a time.”
12–25 minutes · Part 2

State changes and OUTPUT

Show that a program has a current state, and that OUTPUT captures a value at the moment it runs.

Talk track“The computer does not automatically redo an earlier calculation when a variable changes. It only executes the instructions we give it. What if we wanted these calculations to solve a real problem?”
25–48 minutes · Parts 3 & 4

Build geometry algorithms

Connect stored values to the area formulas students are studying. After examples, let tables create and exchange original algorithms.

Intro prompt“So far, we have been changing numbers just to see what happens. What if our numbers represented something useful—like length and width? Could we build a reusable area calculator?”
Table challenge (about 18 minutes): Choose a rectangle, triangle, parallelogram, or trapezoid. Set dimensions, calculate area, and OUTPUT it. Then change a dimension and add a new calculation. Exchange with another table: can they predict both outputs? Fast finisher: change a dimension three times but recalculate area only twice.
48–57 minutes · Optional Part 5

Die rolls and IF / ELSE

A stretch goal only if geometry wraps up early. Use a six-sided die to make the value of roll unknown until execution.

57–60 minutes · Closing

Reflection

Why doesn't an earlier calculation update automatically? Why does the order of instructions matter? How is an algorithm different from answering one math question?
